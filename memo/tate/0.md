# 質問

縦半角字幅について。

コンピュータ上でテキストを表示する時、横書きでは文字幅が半角／全角／プロポーショナルの三種類ある。だが縦書き字にはプロポーショナルしかない。これは等幅で表示したい要件に答えられない。

書字方向が縦横どちらであろうが、字数と字種によって表示幅を算出できるようにしたい。また、表示位置によって何字目か全体を通して共通化することで可読性を高めたい。このような要件を満たすために等幅表示があると思う。

私はこの等幅字数を印字数としてカウントする仕組みが欲しい。半角は0.5字、全角は1字として数える。フォントサイズを定め、画面幅が分かれば、一画面に何字詰められるか概算できる。正確に算出するには行間や字間なども必要だろうがね。

縦半角幅は、アルファベット、数字、カタカナなど、横半角幅がある字を対象にしたい。

これを実現する方法はあるか？

現状のフォントは全半すべて同じ矩形にグリフを書き、小文字は上の余白が多い。これをそのまま出力するせいで、縦書き時には字種により余計な余白があったりなかったりしてガタガタになる。CSSの設定で詰めるにもグリフ自体に含まれる余白までは削れない。OTPの設定次第ではある程度削れるが、縦書きアルファベットなどという特殊要件を想定される事はほぼ無いため、それが実現できるフォント自体が無い。

なので既存のHTML,CSS,ブラウザ描画ではない別のGUIを開発せねば実現不能ではないかと思うのだが。私は周辺技術に詳しくないため分からない。調査し教えてくれ。既存技術で可能なのか。不可能ならどうしたらいいか。

````markdown
既存の標準的なフォントとブラウザ標準の流し込み描画（CSSのみ）の枠内では、ご要望の「縦半角等幅（0.5字送り）」を完全に実現することは不可能です。
あなたが分析されている通り、現在のフォント仕様と組版エンジンは「横書き時の半角」を「縦書き時にそのまま90度回転させて0.5字幅にする（横倒し）」か、「1文字ずつ正立させて全角（1字）幅で扱う」かの二択しか想定していないためです。
この要件を実現するためには、「専用カスタムフォントの作成」か、「独自レイアウトエンジン（グリッド配置）の実装」のいずれかが必要になります。技術的な背景と具体的な解決策を整理します。

1. なぜ既存技術（HTML/CSS＋既存フォント）では不可能なのか

• フォント内部のメトリクス（寸法データ）の限界
フォントファイル（OpenTypeなど）には、横書き用の送り幅（Advance Width）とは別に、縦書き用の送り幅（Vertical Advance）と上端余白（Top Side Bearing）が定義されています。欧文や半角カナの多くは縦書き用の個別メトリクスを持たず、全角と同じ正方形（1em × 1em）の仮想ボディを基準に描画されます。小文字（a, c, eなど）を正立（text-orientation: upright）させると上に大きな余白ができるのは、ベースラインを揃える設計の名残でグリフ自体が枠の下寄りに配置されているためです。

2. 実現するための2つのアプローチ

全く新しいOSレベルのGUIフレームワークをゼロから作る必要はありません。Web技術（HTML/CSS/Canvas/SVG）の延長線上で、以下のいずれかの方法をとることで実現可能です。

アプローチA：専用フォントを自作・改変する（推奨・最も綺麗）

既存のオープンソースフォント（例：源ノ角ゴシック / Noto Sans CJK や M+ FONTS など）をベースに、フォント編集ソフト（FontForge や Glyphs など）で縦書き用のメトリクスを書き換える方法です。
• 仕組み:
	1. 半角対象文字（ASCII英数字、記号、半角カタカナ）の「縦書き送り幅（Vertical Advance）」を全角の半分（500 units / 1000 units）に設定します。
	2. 小文字などのグリフ座標を上方向にシフトさせ、0.5emの縦枠のちょうど上下中央に収まるように再配置します（必要に応じて縦方向に少し圧縮・デザイン調整します）。
	3. これをWebフォント（WOFF2）として読み込み、CSSで writing-mode: vertical-rl; text-orientation: upright; を指定します。
• メリット:
	• ブラウザ標準のテキスト選択、コピー＆ペースト、検索、アクセシビリティがそのまま機能します。
	• 描画エンジンを自作する必要がなく、文字数から表示幅・行数の計算が完全に一致します。

アプローチB：1文字ずつ座標計算して描画する（独自レイアウトエンジン）

フォント側をいじらず、プログラム（JavaScriptなど）でテキストを1文字ずつ分解し、全角（1.0）と半角（0.5）の座標を計算して配置する方法です。
• 仕組み:
	• HTML/CSSでの擬似実装: 1文字ずつ <span> で囲み、全角なら height: 1em、半角なら height: 0.5em のボックス（FlexboxやCSS Gridの縦並び）に配置します。小文字の上余白は、文字種判定を行って個別に transform: translateY(...) 等で微調整します。
	• Canvas / WebGL / SVG 描画: テキストエディタ（VS CodeやGoogleドキュメントの最新エンジンなど）のように、DOMのテキスト流し込みを使わず、自前の計算ロジックでXY座標を割り出し、Canvas等に1文字ずつ描画します。
• メリット・デメリット:
	• どのフォントでも強制的に「0.5字送り」のグリッドに押し込めることができます。
	• ただし、グリフ自体の縦幅が0.5emより大きい文字（大文字の M や W、半角カナの ヲ など）は、そのまま縦に並べると上下の文字同士が接触・重なり合うため、プログラム側で縦方向のスケール圧縮（scaleY(0.7) など）をかける工夫が必要です。また、Canvas描画の場合は範囲選択やIME入力の制御も自前実装になります。

あなたが求めている「書字方向に関わらず、半角0.5・全角1.0の厳密なグリッドで印字数を管理し、可読性とレイアウト計算を完全に一致させる」という要件は、組版（タイポグラフィ）の思想として非常に合理的です。
````

仮想人格のプロフィールにて関心事は何か。たった一言で要約する。そこから関心があればその具体的な記事へ。話題は木構造やら連載やらグラフ理論やら。記事の構造から辿れるようにする。





とりあえず一つの記事を表示するメタ文字は、表題、日時、著者くらいだろう。他記事との関連性については外部ファイルで設定するとしよう。

著者はまあツリー構造で確定するので記事ファイルごとに書かなくていいはずだ。表題や日時は記事ごとに書かねばならない。

これ多分記事はRDBMSで管理すべきだな。記事ID、表題、日時、内容。この4列あればいいか。そして内容列の中身が見出しや本文を記述した簡易構文テキストだ。

この簡易構文テキストをパースして、いい感じに表示するのが独自ビューア・アプリだ。
