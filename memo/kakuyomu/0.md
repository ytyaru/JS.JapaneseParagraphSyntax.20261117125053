おっしゃるロジックは、実務のテキスト処理において非常に理にかなった王道の手法です。整理すると、あなたの推測は以下の通りですね。
1. HTML文字参照によるエスケープ手法:
｜《 を先に &#x300A;（や &#12298;）に置換してしまえば、後続の正規表現 /...《...》/ に一切引っかからなくなり、ブラウザ上ではそのまま 《 と表示される。わざわざトークン配列を作って復元処理を書く必要すらない。
2. AST/Token化の不要論:
カクヨムは構文が「ルビ」「傍点」「エスケープ」の3つしかなく、出力先もHTML一択。わざわざ重いASTやトークン化を実装するメリットが薄く、正規表現の連続置換（replace）で直接HTML文字列に変換している可能性が極めて高い。
3. パイプ省略形の開始位置の特定:
パイプなしルビ（漢字《かんじ》）は開始の制御記号がないため、1文字ずつ読むステートマシンでは「漢字が来た時点でルビの親文字になるか先読みし続ける」という無謀な処理になる。結局、正規表現エンジン（バックトラックや文字クラス [一-龠...]+）に任せるのが最も合理的。

HTML文字参照方式で書く場合の厳密な正規表現パイプライン

あなたの推測されたアーキテクチャ（HTML文字参照への退避 ＋ 正規表現の連続置換 ＋ メタ文字の厳密な除外）をそのままコードに落とすと、驚くほどシンプルで堅牢になります。
javascript
function parseKakuyomuDirect(text) {
  return text
    // 1. HTML特殊文字の無害化
    .replace(/&/g, '&amp;')
    .replace(/</g, '&lt;')
    .replace(/>/g, '&gt;')

    // 2. エスケープ処理：｜《 を HTML文字参照 &#x300A; に置換して後続の正規表現から完全に逃がす
    // ※漢字の直後（漢字｜《...》）であっても、ここで &#x300A; に変わるためルビ化しない
    .replace(/[|｜]《/g, '&#x300A;')

    // 3. 傍点：《《...》》 ※内部に 《 や 》 や改行を含まないように制限
    .replace(/《《([^《》\n]+?)》》/g, '<em class="emphasis">$1</em>')

    // 4. パイプありルビ：｜親文字《ルビ》 ※親文字・ルビ共にメタ文字と改行を厳密に除外
    .replace(/[|｜]([^|｜《》\n]+?)《([^《》\n]+?)》/g, '<ruby>$1<rt>$2</rt></ruby>')

    // 5. パイプなしルビ：漢字《ルビ》
    // ※ステップ2で ｜《 が &#x300A; になっているため、漢字｜《...》 はここでは絶対にマッチしない
    .replace(/([一-龠々仝〆〇ヶ]+)《([^《》\n]+?)》/g, '<ruby>$1<rt>$2</rt></ruby>');
}
コードは注意してご使用ください。

この方式（HTML文字参照退避＋正規表現）が優れている理由

• 「漢字｜《ルビにしない》」のバグが構造上起きない
ステップ2の時点で 漢字&#x300A;ルビにしない》 になるため、ステップ5の 漢字《...》 の正規表現が誤爆する余地がゼロになります。
• 後処理（復元ループ）が不要
ブラウザがHTMLをレンダリングする際に &#x300A; を自動的に 《 として描画してくれるため、独自プレースホルダを元に戻す処理すら不要です。
• メタ文字の厳密な除外
[^|｜《》\n]+? を徹底することで、parser.ts のような「別のルビを跨いで誤マッチするバグ」も完全に防げます。
実際のカクヨムのバックエンド（Perl / Go / JS等）でも、構文の少なさとパフォーマンスの観点から、まさにこのように「エスケープ記号を文字参照（または一時コード）へ逃がしてから正規表現で一括置換する」という実装が採られている可能性が非常に高いです。

ご指摘の通りです。2点とも私の正規表現に甘さがありました。

1. ルビ内のパイプ文字 | ｜ の除外漏れ

ルビ側（《...》 の中身）でも、別のルビ開始記号を跨いで誤爆しないよう [^|｜《》\n]+? とすべきでした。
（例：｜親《ルビ1｜親2《ルビ2》 のような不正・未閉じの入力が来たときに、パイプを跨いで吸ってしまうのを防ぐためです）

2. 漢字・踊り字・異体字セレクタの網羅不足

[一-龠々仝〆〇ヶ] は昭和期からよく使われる雑なイディオムであり、現代のUnicode環境では以下の文字がすべて抜け落ちます。
• Unicode漢字ブロックの漏れ: \p{Script=Han}（\p{Han}）を使うことで、CJK統合漢字の拡張A〜I（サロゲートペア領域の漢字）や互換漢字をすべて網羅できます（u フラグ必須）。
• 踊り字・記号類:
	• 々（同の字点）、仝（同上）、〆（しめ）、〇（漢数字のゼロ）、ヶ・ヵ（小書きのケ・カ）※これらは \p{Han} に含まれないものがある（特に 〆 〇 ヶ ヵ）ため明示が必要です。
	• 〻（二の字点：縦書き小説で頻出する漢字の踊り字 \u303B）
• 異体字セレクタ（IVS / SVS）:
	• 漢字の直後に付く \uFE00-\uFE0F（SVS）および \u{E0100}-\u{E01EF}（IVS：サロゲートペア）を含めないと、異体字の途中でマッチが分断されます。

• Unicodeプロパティエスケープ（\p{Script=Han} ＋ u フラグ）: サロゲートペア領域の漢字（𠮷野家の「𠮷」など）でも1文字として正しく認識されます。
