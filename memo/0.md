# 日本語段落構文(JapaneseParagraphSyntax)

日本人が文書を記述する時、高品質にすべくHTMLやMarkdownで記述する。だがこれらの構文体系は英語圏を基準にしている。例えば文書構造は英語圏なら段落だけで済む。だが日本語には意味段落と形式段落がある。これをHTMLで表現しようとしてもできない。それっぽく見せるためにbrやCSSを組合せねばならない。

```jd
意味段落１

意味段落２


意味段落３



意味段落４中形式段落１
意味段落４中形式段落２
意味段落４中形式段落３
```
```jaml
<p1>意味段落１</p1>
<p1 br=1>意味段落２</p1>
<p1 br=2>意味段落３</p1>
<p1>
<p2>意味段落４中形式段落１</p2>
<p2>意味段落４中形式段落２</p2>
<p2>意味段落４中形式段落３</p2>
</p1>
```
```html
<style>
p { margin: 0; }
p + p { margin-top: 1em; }
</style>
<p>　意味段落１</p>
<p>　意味段落２</p>
<br>
<p>　意味段落３</p>
<br>
<br>
<p>
　意味段落４中形式段落１
<br>
　意味段落４中形式段落２
<br>
　意味段落４中形式段落３<
</p>
```

全角スペースをCSS余白にしたり、段落間改行をCSS余白にすることは可能だ。しかしブラウザからテキストコピーした時、全角スペース文字や改行コードにならない。それらを文字として埋め込んだほうが、テキストエディタという文脈において再現性を高める事ができる。

しかしそうなると全角スペースが各所に放り込まれることになり一元管理・編集・修正できない。作品全体を通じて字下げを共通化させたいのか、それとも全て全角スペースを手入力するようにすべきか、または混在させるべきか。

JSを利用し入力データに全角スペースがあるか否かに関わらず形式段落の冒頭は常に設定に基づいたテキストを動的生成するようにすべきだろう。設定が全角スペースありならそうし、なしならそうする。統一せずにテキストそのままなら、そうする。要するにコピーするテキストの字下げは設定またはコピー方法の選択次第でその内容を動的に変更させることが可能な状態にする。これが最も汎用性の高い仕組みだ。

拡張子|全名|和名|概要
------|----|----|----
AST|-|jd,jmlの構文木（どちらも表現形式が違うだけで本質はこの構文木であり同じ内容になる）
jd|Japanese Markdown|jmlの簡易構文
jml|Japanese Markup Language|html類似の日本語文章構造のみ抽出した言語
html|Hyper Text Markup Language|リンク可能な文書の構造を定義する言語

## jd

* 拡張子: jd
* 文字セット: Unicode
* BOMの有無: 不問
* Unicode正規化: 不問
* メタ文字: 改行コード（`\n`）

これは日本語の文章構造を定義する。自然なテキストの形であり、この見た目と同じようにHTML出力される想定。

Windowsの場合は改行コードが`\r\n`だが、規格上は`\n`のみがメタ文字である。今回の規格に合わせるなら`\r\n`を`\n`に一括置換するのが簡単だが、将来の拡張ではフェンスブロックで`\r\n`があり、それはそのままにしておきたく置換されたら困るという場面がありうる。なので、パース用APIの設定で改行コードを変更できる設定だけ用意しておくのが良いかもしれない。

できれば、文字セット、BOM、Unicode正規化、改行コードといったメタデータをバイナリデータ構造として保持しておくことで、それらのデータを取得して適切なパースを自動設定できるような構造だと助かるのだが。それをするとバイナリデータ化せねばならずテキストエディタでの気楽な編集ができなくなってしまう。なので断念する。

### 空行ルール

* `\n` が1個（改行のみ）：同一 p1 内の p2 と p2 の区切り（形式段落の切り替え）
* `\n` が2個（空行1行）：p1 と p1 の区切り（通常の意味段落の切り替え、br=0）
* `\n` が3個（空行2行）：p1 と p1 の区切り ＋ 1行分の余白（br=1）
* `\n` が N 個（N ≥ 2）：p1 の区切り ＋ br(N - 2個)

## jml

* 意味段落p1
    * トップレベルにのみ存在できる
* 形式段落p2
    * 意味段落p1内にのみ存在できる
* 改行br
    * トップp1間、p1内p2間のみ存在できる（冒頭や末尾は不可）
    * 連続存在できるのはp1間のみ（p1内p2間は常に1個）
* 字下げ
    * p2冒頭のみ設定次第で1字分余白を入れる

これにて日本語の文章構造を適切に表現できるはず。

ただ、文書に応じて字下げをするか否か共通化しないかの設定は可変にしたい。このメタデータをどう記述すべきか。とりあえず以下のように仮定しておこう。

```jml
<style>
<p2 indent="0|1|-"></p2>
</style>

<p1>意味段落１</p1>
<p1 br=1>意味段落２</p1>
<p1 br=2>意味段落３</p1>
<p1>
<p2>意味段落４中形式段落１</p2>
<p2>意味段落４中形式段落２</p2>
<p2>意味段落４中形式段落３</p2>
</p1>
```

もしかすると字下げはjdのlintの制約として定義すべきかもしれない。最初は未定義にしておき、著者が自力で毎回字下げを手書きする。設定次第では常にp2の先頭に1字字下げしていることを強要する。もしそうでない箇所を発見したら、lint制約違反としてユーザに通知する。そういう仕組みにすべきかもしれない。

ただ、字下げをjdの時点でどうするかと、表示時にどうするかは、別問題だ。また、それをテキストコピーするときにどうするか。全角スペースとしてコピーするか。それとも空にしてCSSだけ見た目上の字下げだけがあることにするか。それらを定義した設定記述が必要かもしれない。

* jd記述ルール選択
    * 統一強制（ヒューマンエラー防止）
        * 冒頭全角スペースがなくともp2なら常に字下げする
        * 冒頭全角スペースがあろうとp2なら常に字下げしない
    * 自由（ヒューマンエラー発生するが自由度が高い）
        * 全角スペースがある時だけ字下げする
* ビューアからテキストコピー時（以下の処理に応じてコピーされるテキストが動的に変わる）
    * 字下げは全角スペース文字とする
    * 字下げは何の字も使わない（CSS上における見た目だけの余白とする）

```jd
---config
p2-indent-input: 0|1|-（しない(禁止)／する(強制使用)／任意(全角スペースを入れるか否か次第。混在許容)）
p2-indent-copy: 0|1（しない／する）
---
```

```html
</p>
```

これに加えて以下のようなCSSもデフォルトで使うべきだろう。これをビューア側で設定できるようにすべきか。それとも文書ファイルの設定値で保存できるようにすべきか。

```css
line-height: 1.7em;
letter-spacing: 0.05em;
```

jmlの形式に合わせると以下のようになるか。

```jml
<style>
<p lineHeight="1.7em" letterSpacing="0.05em"></p>
</style>
```
